# 同步能力测试场景与结果

> 分支：`scene_test`
> 文档生成日期：2026-06-12
> 适用版本：cms-xgkb-sync v2.0.9

## 一、背景

本轮工作以"**场景测试驱动**"的方式，为同步引擎补充了两层测试覆盖，并在编写测试的过程中发现并修复了两类真实缺陷：

1. **隐藏目录（`.` 开头）被错误纳入同步** —— 例如 `.obsidian`、`.trash` 等内部目录。
2. **重命名/移动与内容并发变更交叉时内容丢失** —— 改名期间若另一侧内容也发生变更，旧逻辑无法正确取较新内容。

测试分为两层：

- **Mock 场景测试**（`tests/scenes/syncAbility.scenario.test.ts`）：内存模拟本地/云端文件系统，快速验证同步引擎的决策与收敛逻辑。
- **真实云端冒烟测试**（`tests/scenes/realCloudSync.smoke.test.ts`）：连接真实 XGKB 云端 API，端到端验证完整同步链路（未配置云端凭据时自动跳过）。

## 二、配套的功能性修复

| 文件 | 改动 | 说明 |
|------|------|------|
| `src/syncFileTypes.ts` | 新增 `pathHasDotFolder()` | 判定路径的父级目录中是否存在 `.` 开头的隐藏目录 |
| `src/fsXgkb.ts` | 遍历云端列表时跳过隐藏目录 | 避免 `.obsidian` 等内部目录被卷入同步 |
| `src/syncEngine.ts` | 修正双向 rename 权威方判定 | 本地未真正改动时直接 `rename-local`，不再误判权威方 |
| `src/syncEngine.ts` | `doRenameRemote` 增加内容并发处理 | 引入 `shouldUploadLocal` / `shouldDownloadRemote`，按 mtime 决定上传本地或下载远端内容，并正确记录实际 mtime 入库 |

## 三、测试场景清单

### A. Mock 场景测试（17 个用例）

| # | 场景 | 验证点 |
|---|------|--------|
| 1 | 首次双向同步 | 本地文件上传、云端文件下载 |
| 2 | 双向更新传播 | 本地改动与云端改动各自传到对端 |
| 3 | 删除同步 | 本地删除 + 云端显式删除均能同步 |
| 4 | 文件改名 / 移动 | 双向的文件 rename、move |
| 5 | 目录改名 / 移动 | 双向的文件夹 rename、move |
| 6 | 同文件冲突 | 按较新的 mtime 决定权威方 |
| 7 | 首次同路径冲突 | 同路径首次同步不产生重复文件 |
| 8 | 下载失败重试 | 失败的下载下次同步重试并收敛 |
| 9 | 远端 rename 优先 | 本地未改动时即使本地 mtime 更新，也接受远端改名 |
| 10 | 缺失远端条目的保护 | 没有确认删除时，远端条目缺失不删本地文件 |
| 11 | 改名 × 云端更新交叉 | 本地改名同时云端内容更新 → 保留云端内容 |
| 12 | 本地更新 × 云端移动冲突 | 收敛且不产生重复路径 |
| 13 | 删除冲突 | 删除冲突的确定性解决 |
| 14 | 上传失败重试 | 失败的上传下次同步重试并收敛 |
| 15 | 高难度路径批量 | 大量文件、深层目录、空文件、大文件、特殊字符 markdown 路径 |
| 16 | 仅大小写改名 | case-only rename 不会重建旧路径（大小写不敏感坑） |
| 17 | 忽略范围外内容 | 附件、`.obsidian` 配置目录等不纳入同步 |

### B. 真实云端冒烟测试（5 个用例）

| # | 场景 | 验证点 |
|---|------|--------|
| 1 | 完整往返 | create / update / rename / move / delete 对真实云端的一轮往返 |
| 2 | 真实本地文件夹 → 云端 | 从真实本地测试目录执行操作，再用 API 反查云端状态核对 |
| 3 | 云端 → 本地拉取 | 云端的 create / update / rename / move / delete 正确拉进本地文件夹 |
| 4 | 20 个特殊命名文件 | 批量同步 + 幂等性（再次同步无多余操作） |
| 5 | 链式本地操作 | 批量、嵌套目录、特殊命名、连续链式操作同步到真实云端 |

### 覆盖维度总览

- **操作类型**：增 / 删 / 改 / 改名 / 移动，单文件与目录
- **方向**：本地 → 云、云 → 本地、双向
- **冲突解决**：同文件冲突、同路径冲突、改名 × 更新交叉、删除冲突、移动 × 更新冲突
- **健壮性**：上传/下载失败重试、幂等性、缺失条目保护
- **边界路径**：大小写、特殊字符、深层嵌套、空文件、大文件、隐藏目录排除

## 四、如何运行

```bash
# Mock 场景测试
npm run test:sync-scenes

# 真实云端冒烟测试（需在 .env.test.local 配置云端凭据，否则自动跳过）
npm run test:sync-real-cloud
```
