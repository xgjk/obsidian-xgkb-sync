# Obsidian × 玄关知识库同步 — 业务说明

> 本文面向产品、业务负责人及首次接触本插件的协作者，说明**这个插件解决什么问题、适用谁、以及系统如何运转**。  
> 安装与配置见 [README.md](../README.md)；同步作用域与水位设计见 [sync-scope-and-watermark.md](./sync-scope-and-watermark.md)、[sync-pipeline-and-watermark.md](./sync-pipeline-and-watermark.md)。

---

## 1. 项目是什么

**XGKB Sync**（Obsidian 社区插件，ID：`cms-xgkb-sync`）是一个运行在 **Obsidian 笔记应用内**的同步插件，负责把用户在本地 Vault 中编辑的 Markdown 笔记，与**玄关知识库（XGKB）**云端目录保持同步。

可以把它理解成：

- **Obsidian 的「云端备份与协作出口」**：在 Obsidian 里写笔记，自动或手动同步到知识库，供团队检索、分享、在网页端继续编辑。
- **知识库的「本地编辑窗口」**（双向模式下）：云端文档变更也会拉回 Obsidian，继续用 Obsidian 的编辑体验加工。
- **个人知识工作者的桥接工具**：面向「习惯 Obsidian、但公司知识沉淀在 XGKB」的用户，无需离开 Obsidian 即可完成双向同步。

与 **openclaw-xgkb-sync**（服务器后台 Agent）不同：本插件**依赖 Obsidian 客户端**，在用户电脑上运行，适合个人桌面场景，而非 OpenClaw 沙箱/服务器无人值守同步。

---

## 2. 解决什么问题

| 痛点 | 本插件的做法 |
|------|----------------|
| Obsidian 笔记只在本地，无法进入公司知识库 | 配置云端目标目录后，一键或定时同步 `.md` 文件 |
| 网页知识库与本地笔记各写各的，容易分叉 | **双向同步 + LWW（Last Write Wins）**，按修改时间自动合并 |
| 只想同步某个文件夹，不想动整个 Vault | 支持指定 **Sync folder**（空则同步整个 Vault） |
| 换云端目录或空间后同步「漏文件」 | **多同步作用域（Sync Scope）**：不同目标各自维护水位，切换目标可预期 |
| 增量同步卡住、失败文件反复漏 | 水位推进 + 失败记录优先重试（见 [sync-pipeline-and-watermark.md](./sync-pipeline-and-watermark.md)） |
| 不会写命令行，需要可视化配置 | Obsidian **设置页** + 侧边栏刷新按钮 + 命令面板「Sync now」 |

## 3. 典型使用场景

### 3.1 个人笔记归档到知识库

- **本地**：Obsidian Vault 下的 `notes/` 或整个库。
- **云端**：知识库个人空间下的 `Obsidian/` 或自定义路径。
- **方向**：**push（仅推送）**，本地为准，云端作为归档与检索入口。

### 3.2 团队知识双向协作

- 业务人员在知识库网页端修订规范文档，作者在 Obsidian 继续撰写同一批文件。
- **方向**：**bidirectional（双向）**，冲突时修改时间较新的一方覆盖。

### 3.3 从知识库拉取模板与参考

- 新人 Obsidian 库需要从公司知识库拉取 onboarding 材料。
- **方向**：**pull（仅拉取）**，以云端为准更新本地。

### 3.4 多目标切换

- 同一 Vault 需要在「个人空间 / Obsidian」与「项目空间 / A/B」之间切换同步目标。
- 插件为每个**同步作用域**独立保存水位；切回曾用过的目标时沿用历史水位，无需重新全量（在数据仍有效的前提下）。

## 4. 核心概念

### 4.1 同步配置（设置页）

| 配置项 | 业务含义 |
|--------|----------|
| **App Key** | 玄关知识库 Open API 密钥，决定访问身份 |
| **Server URL** | 知识库 API 地址 |
| **Project ID** | 目标知识库空间；留空则使用**个人知识库** |
| **Sync folder** | Obsidian 内参与同步的本地目录；空 = 整个 Vault |
| **Cloud target folder** | 知识库内的同步根目录，如 `Obsidian` 或 `A/B`；不存在时**自动创建** |
| **Sync direction** | `bidirectional` / `push` / `pull` |
| **Automatic sync interval** | 定时自动同步（5 分钟～2 小时，或关闭仅手动） |

### 4.2 同步作用域（Sync Scope）

当用户修改「换空间、换云端目录、换本地同步文件夹、换 API 地址或密钥」等**身份相关配置**时，插件会切换到新的作用域：

- 每个作用域有独立的 **lastSyncTime（水位）** 和 IndexedDB 文件映射。
- 首次使用新目标 → 提示「将执行全量对账」。
- 切回曾用过的目标 → 沿用该目标的历史水位。

仅改同步方向、定时间隔等**行为配置**不会重置水位。

### 4.3 同步方向

| 模式 | 行为 | 适用 |
|------|------|------|
| **push** | 只上传、删远端多余文件 | 本地写作、云端归档 |
| **pull** | 只下载、删本地多余文件 | 以云端为源头的资料同步 |
| **bidirectional** | 两端互相同步，冲突按 mtime | 人机共编 |

## 5. 系统怎么运转（业务视角）

### 5.1 整体架构

```
┌──────────────────┐         Open API          ┌──────────────────┐
│  Obsidian Vault   │  ◄──────────────────────►  │  玄关知识库 XGKB  │
│  本地 .md 笔记     │   上传 / 下载 / 列表 / 删除   │  云端目录与文件   │
└────────┬─────────┘                             └──────────────────┘
         │
         │  扫描、决策、执行（SyncEngine）
         ▼
┌──────────────────┐
│  XGKB Sync 插件   │  ← 设置（data.json）
│  （Obsidian 内）  │  ← IndexedDB 文件状态 + 多作用域水位
└──────────────────┘
```

### 5.2 用户如何触发同步

| 方式 | 说明 |
|------|------|
| 侧边栏 **刷新图标** | 点击即「Sync now」 |
| 命令面板 | `XGKB Sync: Sync now` |
| 自动定时 | 设置页选择间隔（如每 30 分钟） |
| 设置页按钮 | **Test connection**（测连通）、**Diagnostics**（差异诊断） |

同步进行中再次触发会提示「请勿重复点击」，避免并发冲突。

### 5.3 一轮同步在做什么

1. **确定当前作用域**  
   根据 App Key、Server URL、Project ID、本地/云端目录等计算 `scopeKey`，读取该作用域的水位 `lastSyncTime`。

2. **准备远端根目录**  
   解析或创建云端目标文件夹，获得 `rootFileId`。

3. **扫描本地**  
   在 Obsidian Vault 内列出匹配的 `.md` 文件及修改时间。

4. **扫描远端**  
   - 有水位 → **增量**：`listChanges(since)` 拉变更；失败则降级全量。  
   - 无水位 → **全量**：分页列出目标目录下所有文件。

5. **逐文件决策（LWW）**  
   对比本地、远端、IndexedDB 历史记录，决定跳过、上传、下载或删除。

6. **执行**  
   下载优先走 OSS 直链（更快、Vault 即时可见）；上传/删除按队列执行。

7. **更新状态**  
   成功则推进该作用域水位；失败文件记入 IndexedDB，下轮**优先重试**。

**无变更时**：增量模式下若本地与远端均无变化，可快速结束。

### 5.4 文件变更的业务语义

系统以**相对路径**识别文件，不识别操作系统级「重命名事件」：

| 用户操作 | 典型结果（push/双向） |
|----------|------------------------|
| 新建笔记 | 上传到云端 |
| 编辑内容 | 覆盖同步 |
| 删除笔记 | 删除云端对应文件 |
| 重命名文件 | 删云端旧路径 + 上传新路径 |
| 云端网页修改 | 拉回 Obsidian（pull/双向） |
| 两端同时修改 | 修改时间较新者获胜 |

## 6. 与 openclaw-xgkb-sync 的关系

| 维度 | Obsidian XGKB Sync（本插件） | openclaw-xgkb-sync |
|------|------------------------------|---------------------|
| 运行环境 | Obsidian 桌面客户端 | Node.js 后台服务 |
| 典型用户 | 个人知识工作者、作者 | OpenClaw Agent 节点、服务器 |
| 配置方式 | Obsidian 设置页 | `config.json` + Web/API |
| 多目录 | 单 Vault + 可选子文件夹 | 多条 Mapping 并行 |
| 状态存储 | IndexedDB + 插件 data.json | SQLite |
| 核心同步逻辑 | 同源思路（LWW、增量、listChanges） | 同源思路，面向规模化运维 |

两者都对接同一套**玄关知识库 Open API**，可在业务上形成「人写 Obsidian、Agent 写 OpenClaw 工作区、最终都汇入 XGKB」的知识流，但部署形态与受众不同。

## 7. 运维与排错（业务侧）

| 操作 | 入口 |
|------|------|
| 验证 API 与目录权限 | 设置页 **Test connection** |
| 查看本地/云端差异预览 | 设置页 **Diagnostics**（控制台 + `.xgkb-sync-debug.log`） |
| 换目标后强制全量 | **Reset current scope** 或 **Reset all scopes** |
| 查看同步结果 | Obsidian 通知栏摘要（↑上传 ↓下载 ✗删除 失败:N） |

常见问题：

- **未配置 App Key** → 无法同步，需先在设置页填写。
- **换云端目录后拉不下来** → 通常需重置当前作用域或等待新作用域首次全量。
- **部分文件失败** → 水位仍会推进，失败项下次优先重试；详见通知与控制台日志。

---

## 8. 成功标准（业务验收）

1. 设置页 **Test connection** 显示连接成功，且目标目录可访问。
2. 在 Sync folder 内新建或修改 `.md`，手动同步后知识库对应路径可见变更。
3. 再次同步显示「无变化」或仅增量统计，无持续性失败提示。
4. （若双向）在知识库网页修改后，Obsidian 内文件内容随之更新。

## 10. 一句话总结

**XGKB Sync 让 Obsidian 用户在不离开笔记应用的前提下，与玄关知识库保持 Markdown 文件的双向或单向同步**——通过可视化配置定义「本地哪块笔记对应云端哪条路径」，在后台增量执行，并支持多同步目标切换与失败重试。
